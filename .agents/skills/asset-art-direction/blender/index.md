# Blender procedure routes

Read the procedure for the actual problem; don't load all siblings.
Each leaf names its primary D-rule and existing pipeline/code owner, preconditions,
ordered operations, expected output and failure handling. Procedures describe
**later authorized work**; skill installation grants no asset edits or pilot.

| Task/failure | Procedure |
|---|---|
| Mass/role unclear; structure too thin or generic | [Construction/blockout](construction.md) |
| Hard edges, bulging plane shading, faceting/smoothing | [Normals/topology](normals.md) |
| Palette/material separation or color encoding | [Materials/color](materials.md) |
| Crosswise grain, UVs, packed maps, stale generation or custom bake | [UV/maps](uv-maps.md) |
| Floating props/plants, repeated border, receiver shading | [Contacts](contacts.md) |
| Uniform glow, detached runes, stream/foam contacts | [Emission/water](emission-water.md) |
| Prototype edit versus composition placement/propagation | [Libraries](libraries.md) |
| Unit proportions, crossbow/socket scale, deformation/clips | [Units/rigs](units.md) |
| Matched camera/light/color/pose evidence | [Review scenes](review-scenes.md) |
| Selection, axes/pivots, GLB export/round-trip/material evidence | [Export](export.md) |

Prerequisites are conditional: units need attachment/rig context; shared edits
need library ownership; generated map refresh needs channel ownership/backups.
No recipe requires every family/design sibling. Common numeric settings and
command side effects remain with the [pipeline index](../pipeline/index.md).
