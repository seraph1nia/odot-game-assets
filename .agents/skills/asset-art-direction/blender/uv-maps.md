# UVs, painted maps, refresh ownership and bake exceptions

Use for crosswise grain, stretch/seams, missing portable channels or stale maps.
Primary visual owner: [D04](../design/surfaces.md#d04).
Pipeline owners: [painted_finish.py](../../../../tools/asset_pack/painted_finish.py)
(`project_uv`, `texture_material`, `image_map`, `apply`) and
[art_style.TEXTURES/NORMAL_FAMILIES](../../../../tools/asset_pack/art_style.py).
Numeric texture sizes/relief/variation stay with these owners.

## Inputs and preconditions

Canonical asset/source, selected collection/category, reference mark/region,
shared-versus-unique mesh/material/image users, and **generated/manual/mixed channel
ownership**. Preserve .blend, unpacked PNGs and packed images before editing.
Map generation, source saves, bake tests and GLB export need explicit authorization;
`apply()` writes category-local PNGs and changes in-memory datablocks.
For shared edits read [libraries](libraries.md) first.

## UV procedure

1. Inspect actual mesh users and active UV layer. Shared prototype UVs live in
   mesh-local coordinates; instances should reuse mesh data rather than receive
   unique unwraps automatically. Decide if a unique role mark needs an approved
   material/UV variant before duplicating data across a family.
2. `project_uv()` **returns if any UV layer exists**. It creates missing
   `PaintedUV` through dominant-face projection and mesh-local normalization, not
   a general re-unwrap/repair. Inspect existing UV direction/stretch explicitly.
3. For wood on a face containing the mesh's longest axis, the projector puts
   that axis in V; longitudinal grain follows it. Rotated or pre-baked prototype
   geometry can make the longest axis unlike the intended timber length.
   In the UV Editor inspect face direction with a temporary orientation/checker
   view, rotate/align islands intentionally if authorized; never delete good
   manual UVs just to force the projector.
4. Leaves have explicit root→tip UVs in `forest_kit.leaves()`. Preserve that
   orientation/variation across placements. Named crystals/caps/stems use
   cylindrical angle U/height V on side faces; seam loops may exceed U=1 so
   wrapping is intentional. Check facet highlights against seam/face boundaries;
   changing crystal sides/topology can shift them.
5. Confirm finite UVs and export's TEXCOORD_0 coverage. A finite UV layer passes
   a mechanical contract but says nothing about good grain direction or distortion.

## Generated maps and refresh procedure

1. Keep the linear-color/encoding contract: `fields()` samples deterministic
   washes/height; `texture_material()` computes linear maps; `image_map(data=False)`
   encodes generated byte-image RGB once for sRGB storage. Data maps bypass that
   encoding. Don't re-encode imported sRGB images or treat normals as color.
2. Use `painted_finish.apply(collection, category)` only in an approved authoring
   worker after collection/material/UV ownership is established. It traverses
   direct collection objects, projects each shared mesh once, writes PNGs under
   `sources/<category>/textures/`, packs images and tags the collection stage.
   It does not save the .blend itself; builders save afterward.
3. Inspect native Principled links: image Base Color/Roughness, tangent Normal
   Map where required by family, masked Emission Color if strength is positive.
   Default field generation does not require a separate high-poly mesh bake.
4. **Do not equate another `apply()` call with refreshed content:**

   | Existing ownership/state | Safe decision |
   |---|---|
   | Generated, unchanged inputs | Retain generated images/tags; inspect actual links/UVs |
   | Generated, changed field/palette | Plan explicit regeneration of affected images/material users in an isolated build after preserving sources; matching tags/names prevent automatic refresh |
   | Manual painted channel | Preserve/edit that image intentionally; don't delete it or rebuild over it |
   | Mixed/uncertain | Inventory each channel and packed/unpacked source of truth; stop automatic regeneration until ownership is clear |

   `texture_material()` returns on matching `PAINTED_VERSION`; `image_map()`
   reuses a named image independently. Merely bumping the finish version does
   **not** invalidate existing image names. Explicit refresh must account for
   both image and material users/links; global version/name/default changes are
   separately scoped migrations, not a repair shortcut in this docs skill.
5. For a manual image edit, confirm the actual image buffer, category PNG and
   packed copy reflect the intended revision; save/repack deliberately in the
   owned source. Do not assume an old external PNG overrides a packed image.
6. Verify source style and matching embedded GLB channels with existing
   [checks](../pipeline/index.md#checks) after authorized export; compare small-view
   noise/normal depth, not just channel existence.

## Exceptional custom bake (not the default generator)

Use only when an approved unique mark/relief cannot use existing field/image
painting. This is a procedure to validate for the actual Blender runtime, not a
claim that a tested high/low baking framework already exists.

1. Preserve source/maps; use an isolated evidence/authoring copy and identify
   low target versus high/detail mesh. Establish final UVs and consistent export
   triangulation/split normals before tangent-normal baking to avoid changed tangents.
2. Create/select the intended target image and active Image Texture node for each
   low-target material. Image size/format/color space follow the existing channel
   contract; don't invent another numeric map policy.
3. For high→low normals, select detail source(s), make low target active, use Cycles
   Bake **Normal**, tangent space and selected-to-active; set cage/ray distance from
   measured clearance so rays don't capture neighboring pieces. Check a small
   region first. A color-only custom mark should isolate color rather than bake
   the studio's direct/indirect directional illumination into albedo.
4. Inspect seams, mirrored UVs, ray misses, contact contamination and tangent
   orientation under glancing light. Inspect padding/mip/downscale bleed before
   accepting; choose padding from the actual texture/UV usage, not this leaf's
   invented pixel constant. Keep Roughness/Normal Non-Color and color/emission sRGB.
5. Pack/save only approved target maps/source; verify GLB channels and compare
   actual-size appearance. Stop for a runtime/operator mismatch or bake artifacts;
   don't install another runtime, relax checks or create an unapproved fixture.

## Expected output and failures

Portable packed maps, appropriate UV direction, preserved manual paint/shared
mesh reuse and scoped refresh provenance. Missing/unsupported family names,
inactive UVs, stale packed copies and repeated named images are diagnoses, not
reasons to remove validation or regenerate every asset. Neither this leaf nor
installing the skill authorizes map production, calibration renders or a pilot.
