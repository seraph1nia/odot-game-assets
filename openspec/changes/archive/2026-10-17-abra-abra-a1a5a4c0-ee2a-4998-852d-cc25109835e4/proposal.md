# Proposal

## Why

The asset workspace accumulates historical renders, multiple image-size derivatives and successive native UI capture campaigns alongside essential authored content. Reduce the current tracked checkout without losing authored assets, usable references, required exports or active evidence-dependent workflows; ordinary deletion will not reclaim Git history storage.

## What Changes

- Inventory tracked paths, logical payload bytes, exact duplicate images and consumers at base `60ce86f04c02419d9c09d30c2e25931345bf2bf3`; separately report Git/LFS storage and ignored local caches.
- Seek human approval of the bounded selection rules in `design.md` before implementation. Per retained supervisor answer `tracked-size-inventory`, the first Apply task is a read-only inventory; then record an exact keep/remove/consolidate manifest and measured checkout savings before deleting anything. Unknown tracking, sizes and duplicates remain explicitly unmeasured during planning.
- Limit removal candidates to the historical diagnostic PNG roots enumerated in `design.md`, prioritizing unreferenced superseded captures and verified exact duplicates with a retained counterpart. Preserve compact sheets/focals, immutable receipt-bound images and useful comparisons. Do not interpret a folder named `evidence` as disposable by default.
- Preserve editable sources, source texture companions and supplied inputs, required game exports, reference originals/provenance, current catalog images, native runtime resources, licenses and working build/check procedures. Retain uncertain candidates rather than deleting them on inference.
- Update affected Markdown/HTML navigation coherently. Do not prune images required by immutable receipts, active tests or generators; preserve freshness, hash-binding and predecessor checks without rewriting acceptance history.
- Keep disposable captures in existing ignored scratch/cache locations or isolated staging checkouts, explicitly curate persistent evidence, and add a lightweight evidence allowlist/byte-growth check and documented exception process. Preserve hash-bound capture generator bytes.
- Do not rewrite history, migrate historical assets to LFS, regenerate models, re-export assets, change game integration, or delete ignored personal/cache content.

## Capabilities

### New Capabilities

- `repository-evidence-retention`: Auditable, dependency-safe retention and bounded growth of tracked review evidence, with protected asset/reference inputs and explicit deletion approval.

### Modified Capabilities

None. `openspec/specs/` currently contains only `.gitkeep` (inspected with native directory read; shell OpenSpec listing is unavailable to Explore).

## Impact

Expected implementation surfaces are eligible historical diagnostic PNGs, associated Markdown/HTML navigation, a small retention manifest/check and repository maintenance guidance. Current native previews under `docs/ui/catalog/` are also shipping inputs, not merely documentation. Size distribution, exact duplicate groups, eligible path counts and checkout savings are unknown; no minimum saving is promised. `design.md` bounds selection after measurement and requires renewed approval for broader removals. No current-checkout saving implies reclamation of Git history or full-clone storage.
